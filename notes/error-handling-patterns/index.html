Error Handling: Fail Fast vs Graceful Degradation

November 22, 2025

Quick observation from debugging production issues this week.

Pattern#

When a dependency fails (database, cache, external API), you have two choices:

  1. Fail fast: Return error immediately, let caller handle it
  2. Graceful degradation: Fall back to alternative behavior

When to use which#

Fail fast when:

  • Correctness is critical (payments, auth, writes)
  • Partial data is worse than no data
  • Caller can make better decision than you

Graceful degradation when:

  • User experience matters more than perfect data
  • System can function with reduced capability
  • Failure is expected and temporary (cache miss, rate limit)

Example#

User profile service:

  • User core data (name, email): fail fast if database down
  • User preferences (theme, language): degrade to defaults if cache down

The key: think about what happens if this fails, and whether your fallback is worse than an error.
